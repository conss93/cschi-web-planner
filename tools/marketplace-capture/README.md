# 마켓플레이스 블록 목록 수집기

식스샵 프로 마켓플레이스의 블록 목록 데이터를 확보하기 위한 일회성 도구.
기획 에이전트가 "식스샵에서 실제로 조립 가능한 구성"만 제안하려면 블록 카탈로그가 먼저 필요하다.

## 어떻게 동작하나

마켓플레이스의 API 주소도, 화면 구조도 미리 알 필요가 없다.
브라우저를 하나 띄워두고 **사람이 직접 조작하는 동안 오가는 JSON 응답을 전부 받아 적는다.**
그중 블록 이름처럼 보이는 문자열이 들어있는 응답에 `★` 표시를 달아둔다.

DOM 선택자를 쓰지 않으므로 식스샵이 UI를 바꿔도 깨지지 않는다.

## 준비

Node 20 이상이 필요하다.

```bash
npm install
npx playwright install chromium
```

## 실행

```bash
npm run capture
```

브라우저 창이 하나 뜬다. 거기서:

1. **식스샵에 로그인한다** — 첫 실행 때만. 로그인 세션은 `.auth/` 에 저장돼 다음부터는 건너뛴다.
2. 에디터를 열고 **블록 추가 → 마켓플레이스**로 들어간다.
3. 터미널로 돌아와 아래 키를 누른다.

| 키 | 동작 |
|---|---|
| `a` | 목록을 끝까지 자동 스크롤한다. 블록이 나눠 로딩되는 경우 이걸 해야 전부 잡힌다. |
| `s` | 지금 화면의 HTML을 통째로 저장한다. |
| `q` | 저장하고 종료한다. |

JSON 응답은 키를 안 눌러도 계속 자동으로 기록된다.

### 권장 순서

`전체`에서 `a`로 끝까지 스크롤 → `s`
→ 사이드바 카테고리를 하나씩 클릭하며 각각 `a` 누르고 `s`
→ 다 돌았으면 `q`

카테고리를 하나씩 도는 이유는 **어떤 블록이 어느 카테고리에 속하는지**를 알아내기 위해서다.
`전체` 목록만으로는 그 대응 관계를 알 수 없다.

카테고리 목록은 `data/sixshop-categories.json` 에 정리돼 있다 (15개 + 앱).

## 결과물

```
out/marketplace/
├── manifest.json          수집한 응답 목록. ★ 후보가 무엇인지 여기 적힌다.
├── api/                   JSON 응답 원본
└── html/                  화면 HTML 스냅샷
```

끝나면 터미널에 유력 후보가 크기순으로 출력된다.

## 보안

- `.auth/` 에는 **로그인 쿠키와 인증 토큰이 들어있다.** `.gitignore` 에 넣어뒀지만 압축해서 전달하거나 공유 폴더에 두지 말 것.
- `out/` 도 커밋하지 않는다. 응답에 계정 정보가 섞여 있을 수 있다.
- 공유할 때는 `out/marketplace/api/` 안에서 **블록 목록 파일만 골라서** 보낸다. `manifest.json` 을 먼저 열어 어느 파일인지 확인하면 된다.

## 안 될 때

**JSON이 하나도 안 잡힌다** → 서버가 HTML로 미리 그려 내려주는 방식일 수 있다. `s` 로 HTML 스냅샷만 떠도 된다. 거기서 파싱하면 된다.

**`a` 를 눌러도 스크롤이 안 된다** → 마켓플레이스 창을 클릭해 활성화한 뒤 다시 시도한다. 그래도 안 되면 마우스로 직접 끝까지 내리고 `s` 를 누른다. JSON 기록은 어차피 계속 되고 있다.

**로그인이 매번 풀린다** → `.auth/` 쓰기 권한을 확인한다.

**"Executable doesn't exist" 오류** → `npx playwright install chromium` 을 실행한다.
크롬을 이미 다른 곳에 두고 쓰는 환경이라면 `CHROMIUM_PATH` 로 경로를 직접 넘길 수 있다.

## 점검

식스샵 없이도 수집기가 제대로 도는지 확인할 수 있다.

```bash
npm run selftest
```

무한 스크롤과 페이지네이션을 흉내 낸 가짜 마켓플레이스를 띄우고,
블록 300개를 빠짐없이 잡아내는지 검사한다.
